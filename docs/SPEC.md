# Техническое задание CineAgents

Команда: Игнатьев Арсений, Николаева Полина, 3 курс, КФУ, ИТИС.

## Цель

Мы рассматриваем подбор фильмов по запросу пользователя и его истории оценок. В одном проекте объединяем рекомендательные алгоритмы и связанный граф агентов. Основа требований - задания по мультиагентной системе, локальным LLM и RecSys.

## Рекомендательные методы

Мы используем MovieLens 100K и сравниваем content-based по жанрам, item-CF, популярность, Bayesian mean, гибрид и нейросетевую Two-Tower. Обучение и подбор настроек отделяем от итоговой тестовой проверки. Просмотренные и недоступные фильмы исключаем. Для пользователя без истории используем явно отмеченный запасной вариант.

## Агенты

Общий граф LangGraph: планировщик → инструмент рекомендаций → куратор → валидатор → ответ. При отказе валидатора разрешена одна попытка исправления. Планировщик использует Qwen3 0.6B или 1.7B, куратор - Qwen3 1.7B, валидатор - Gemma3 4B. Программа отдельно проверяет номера, количество, отсутствие повторов и жанр.

Для выбора сложности запроса мы используем небольшой Jev-like классификатор с вероятностями и переходом к сильной LLM при низкой уверенности. Это не официальный Jev. В сравнении участвуют пять локальных моделей, результаты сохранены в artifacts/.

Системные промпты, навыки и правила работы храним в отдельных файлах. Инструмент рекомендаций принимает только заданные аргументы; произвольные команды, SQL и внешние адреса модели недоступны.

## Память

Мы разделяем состояние текущего запроса, последние успешные подборки со сроком хранения семь дней и явные предпочтения на 90 дней. Для записей SQLite указываем пользователя, источник, время обновления и срок действия. Поддерживаем исправление предпочтений и удаление памяти пользователя.

## Развёртывание

Мы запускаем приложение в Bubblewrap внутри WSL2. Исходники, данные и модель доступны только для чтения; запись разрешена в runtime. Внешняя сеть и папки Windows недоступны. Запросы к Ollama идут через ограниченный Unix-шлюз. WSL2 сама по себе не является защищённой средой; ограничения общего ядра и выбранных средств описаны в отчёте.

## Проверка результата

Мы оцениваем рекомендации по Precision, Recall, NDCG, HitRate, MRR, охвату каталога, разнообразию, новизне и времени ответа. Отдельно рассматриваем пользователей с историей и без неё. Для моделей проверяем правильность ответа, JSON и следование ограничениям. Для всей системы - успешность сценария, работу памяти, инструментов и валидатора.

Мы сохраняем журналы, этапы запросов, траектории, токены, время и алерты. Непрерывный монитор проверяет API и рекомендации. Итоговые материалы: исходники, результаты экспериментов, семь диаграмм C4, диаграмма последовательности и PDF.

Продуктовые показатели требуют реальных пользователей и в этой работе не измеряются. Перед сдачей необходимо добавить действующую ссылку на репозиторий и предоставить проверяющему доступ.
