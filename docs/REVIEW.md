# Независимое ревью и исправления

В этом разделе мы разбираем результаты отдельной проверки исходников и файлов эксперимента. Для найденных ошибок приводим регрессионные тесты и повторные результаты. Проверка не является гарантией безопасности.

Выявлено и воспроизведено падающими тестами:
1. Gateway использовал номинальные defaults при проверке, но пересылал исходное тело. Исправлено: canonical options материализуются, неизвестные параметры/неограниченный keep_alive/stream запрещены, num_batch ограничен, concurrency=1.
2. Negative sampling включал 28 недоступных к train cutoff фильмов. Исправлено: negatives только из availability-mask. Обучение и показатели пересчитаны. Первая версия результатов сохранена в artifacts/initial и не является финальным результатом.
3. При cold start popularity называлась запрошенным нейросетевым методом. Исправлено: requested_method, фактический method и fallback_reason разделены.
4. accepted=true с непустыми issues допускал противоречивый успешный ответ. Исправлено: такой ответ отклоняется, допускается один repair.

До исправлений 9 новых регрессионных тестов упали; после исправлений полный набор: 29 passed. Реальные испытания первой версии выявили ложные отклонения валидатора: 2 из 5 сценариев не завершились успешно. Validator payload сокращён до проверяемого журнала ID/count/checks; повторные результаты публикуются отдельно, ошибки первой версии сохранены.

Уязвимости ядра и справедливость рекомендаций для разных групп пользователей мы отдельно не оценивали. Проверка не обнаружила использования тестовой выборки для выбора модели или смешивания памяти пользователей. Для итоговых исправлений мы используем автоматические тесты; отдельной повторной экспертизы нет.

Дополнительный аудит исходных данных обнаружил 61 train-взаимодействие (43 положительных) с тремя фильмами, чьи даты релиза неизвестны или позже cutoff. Сырые наблюдения остаются в seen, но такие предметы исключены из положительных профилей и нейросетевых train pairs. Добавлен отдельный регрессионный тест, обучение повторено. Это не утечка holdout ratings, а несогласованность метаданных, которую нельзя молча игнорировать при выбранной консервативной availability policy.
